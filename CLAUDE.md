# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A single-page Tetris implementation in vanilla JavaScript (no dependencies, no build step, no package.json). Three files: `index.html` (DOM/canvas structure), `style.css` (dark/retro arcade styling), `game.js` (all game logic, ~300 lines).

## Running

Open `index.html` directly in a browser, or serve it statically:

```bash
python3 -m http.server 8000
# or
npx serve .
```

There is no build, lint, or test tooling in this repo.

## Architecture (`game.js`)

Everything lives in one file with module-level mutable state (`board`, `current`, `next`, `score`, `lines`, `level`, `paused`, `gameOver`, `dropInterval`, etc.) — no classes, no modules.

- **Board model**: `ROWS × COLS` matrix; each cell is `0` (empty), a piece color index `1–12`, or `WILD` (13, a comodín — see Power-ups below). `POWER` (14) is a `COLORS`-only paint index; it never appears on the board. `GARBAGE` (15, "basura") is a challenge-mode-only board value — like `POWER`, it lives in `COLORS` but never in `PIECES`/`makePiece`, so `randomPiece()` can never draw it.
- **Pieces**: `PIECES` array of square/rectangular matrices (index 0 unused/null), 1–12. Rotation (`rotateCW`) is transpose + row reversal, not stored per-piece rotation states — it works for any matrix shape (3×3, 4×4, 1×1), which is what let the pentominoes below drop in with no changes to rotation/collision/line-clear/render code. Index 8 (`NUT`) is a 3×3 "tuerca" challenge piece — a ring with a non-colliding hole in the center (`[[8,8,8],[8,0,8],[8,8,8]]`); its hole is rendered as a real circle (`drawNutHole`, canvas `destination-out`) both mid-air and once locked (`isNutHole` detects a locked ring by checking all 8 neighbors of an empty cell).
  - **Pentominoes** (5-cell pieces): `PLUS` (9, `+`/X-pentomino — rotationally symmetric, so `tryRotate` produces an identical matrix and is a harmless no-op), `UPENT` (10, `U`), `YPENT` (11, `Y`, the only 4×4 piece besides `I`).
  - **`SINGLE`** (12, `[[12]]`) is a 1×1 reward piece, delivered only after a Tetris (see below) — never drawn by chance.
  - **Draw pools**: `randomPiece()` no longer draws uniformly over `PIECES.length - 1`; it picks from `STANDARD` (the 7 classic tetrominoes) or, with probability `RARE_CHANCE` (0.12), from `RARE` (`NUT`, `PLUS`, `UPENT`, `YPENT`). Both pools resolve to a piece via `makePiece(type)`, which deep-copies the shape from `PIECES` (so `tryRotate` can mutate it) — `powerPiece()` still builds its own object by hand since it carries an extra `power` field.
- **Collision** (`collide`): checks board bounds and overlap with locked cells. `WILD` cells are excluded from the overlap check — comodines are walkable/passable.
- **Piece queue & rewards** (`nextQueue`): an array kept at *at least* `PREVIEW_MAX` (5) real piece objects — what the panel shows is exactly what falls next, no token indirection. `spawn()` (used by both `init()` and `lockPiece()` instead of calling `randomPiece()` directly) shifts `nextQueue[0]` into `current` and refills up to `PREVIEW_MAX` with `randomPiece()`. `queueRewards(cleared)` — called from both the power-up and normal branches of `lockPiece()`, so it's the one place shared between them — inserts a `SINGLE` piece on a 4-line clear (Tetris) and a `powerPiece()` every `POWER_LINES` (5) lines cleared (counter uses `-=` rather than `%` so an overshoot keeps its remainder toward the next threshold) at **index 1**, not the end: index 0 is the piece `spawn()` is about to promote to `current`, so index 1 is the next preview the player actually sees — the same immediacy the old token-queue gave (queueing at the end would delay a reward by `PREVIEW_MAX` pieces). Both rewards, when they coincide, are collected into one array and inserted with a single `splice(1, 0, ...)` call — that's what keeps single-before-power order intact; two separate `splice(1)` calls would reverse it.
- **Power-ups**: a `powerPiece()` is a normal falling/rotatable 1×1 piece (`type = POWER`) carrying a random entry from `POWERS`, delivered via the reward queue above.
  - The effect fires in `lockPiece()` when `current.type === POWER`: the piece is *not* merged into the board (`applyPower()` runs instead of `merge()`), then `clearLines()` runs as usual so an effect that completes a row (Gravedad, Tinte) still scores.
  - **Bomba**/**Rayo** (`powerBomba`/`powerRayo`) clear a 3×3 area / the full row+column through the landing cell via `destroyCell()` (bounds-checked), scoring `10 × level` per destroyed cell (`scorePower`).
  - **Tinte** (`powerTinte`) finds the most frequent non-`WILD` color on the board and turns every cell of that color into `WILD`.
  - **Gravedad** (`powerGravedad`) compacts each column independently (bottom-up write pointer) so every block falls until it rests — can break a locked tuerca's ring, which `isNutHole` already handles gracefully by no longer recognizing the hole.
  - **Congelar** sets `freezeRemaining = FREEZE_MS`; `loop()` counts it down using the frame's `dt` instead of `setTimeout`, so it naturally stops during pause (`togglePause()` cancels the rAF) and needs no cleanup on `endGame()`/`init()` beyond resetting the variable. Player input (move/rotate/soft/hard drop) is unaffected — only the automatic drop is paused.
  - A temporary banner (`showBanner`/`hideBanner`, `#power-banner` in `index.html`) names the effect on activation and fades out after `BANNER_MS`.
- **Combo/T-spin/B2B/Perfect Clear**: `clearLines()` only mutates the board and returns `cleared` (it no longer scores or queues rewards); `lockPiece()` calls `queueRewards(cleared)` (the `nextQueue`-insertion and energy-gain logic, shared by the power-up branch and the normal branch) and, only for a normal piece, `resolveClear(cleared, isTSpin)`. A power-up's own effect (e.g. Gravedad/Tinte completing a row) goes through `queueRewards` but **not** `resolveClear` — it can't build/break combo or B2B, and never competes with a combo banner for the shared `#power-banner` element.
  - **T-spin**: `T_PIECE = 3`. `lastActionWasRotate` is set `true` only inside `tryRotate()` on a successful rotation, and `false` on any translation (`ArrowLeft`/`ArrowRight`, `softDrop`, gravity in `loop()`) or on `spawn()`/`init()`. At lock time, `countBlockedCorners(px, py)` counts how many of the T piece's 3×3 bounding-box corners are occupied (out of bounds or a locked cell); `isTSpin` requires the piece to be a T, `lastActionWasRotate`, and ≥3 blocked corners. `hardDrop()` needs no special handling: `lockPiece()` only ever runs once the piece truly can't fall further, so the position checked is always the real landing spot regardless of path. By piece geometry, a T-spin can clear at most 3 lines and a 4-line Tetris can never be a T-spin, so the two bonuses never overlap for the same lock.
  - **Combo**: `combo` increments (capped at `COMBO_CAP`) on any lock that clears ≥1 line, and resets to `0` on a lock that clears none (a 0-line T-spin still resets it, per its own literal "no lines cleared" reading). The line-clear score (`LINE_SCORES[cleared]` or, for a T-spin, `TSPIN_SCORES[cleared]`, both `× level`) is multiplied by `combo`.
  - **B2B**: `btbTetris` increments on a 4-line clear and adds a `+BTB_BONUS_RATIO` bonus from the 2nd consecutive Tetris onward; it resets to `0` on any 1–3 line clear but is untouched by a 0-line lock (standard Tetris B2B semantics — only T-spin is a separate bonus, deliberately not sharing this counter).
  - **Perfect Clear**: `isBoardEmpty()` checked after `clearLines()`; adds a flat `PERFECT_CLEAR_BONUS × level`, additive and **not** multiplied by `combo`.
  - All of the above funnel through `scoreEvent(points, info)`, which applies `points` to `score` and, only when the lock is "notable" (T-spin, Tetris, `combo ≥ 2`, or Perfect Clear — a plain single/double/triple with no combo stays silent on purpose), calls `showClearBanner()` (builds one combined `{icono, nombre, desc}` — e.g. `"TETRIS · B2B ×2 · COMBO ×3"` — reusing the exact same `showBanner()` power-ups use, plus a CSS `flash-perfect` pulse on `.game-container` for a Perfect Clear) and `playClearSound()`.
  - **Sound**: Web Audio API only, no assets. `ensureAudio()` lazily creates/resumes a single `audioCtx` on the first `keydown` (browser autoplay policy requires a user gesture). `playTone(freq, ms, delayMs, type, gain)` is a short oscillator blip with an exponential gain ramp-down; `playClearSound()` picks a distinct cue per event (a short arpeggio for Perfect Clear/Tetris, a two-tone blip for T-spin, a single tone whose pitch rises with `combo` otherwise). `muted` (persisted to `localStorage['tetris-muted']`, toggled by `#sound-toggle`) gates `playTone` itself, so every call site stays a plain unconditional function call.
- **Chargeable abilities** (`ABILITIES`, `energy`, `choosingAbility`): the active counterpart to the random power-ups above — the player chooses when and which, instead of receiving one at random. `queueRewards()` also adds `cleared * ENERGY_PER_LINE` to `energy` (capped at `ENERGY_MAX`) whenever any line is cleared, in either `lockPiece()` branch — the same reason `queueRewards` already sits on both branches, so a power-up's own clear (Gravedad/Tinte completing a row) charges the bar too. At `ENERGY_MAX`, `E` (`openAbilityMenu()`) freezes the run exactly like pause (cancels the rAF; `closeAbilityMenu()` resets `lastTime` before requesting a new frame, so no elapsed time leaks into `dropAccum`/`challengeRemaining`/`freezeRemaining`/`slowRemaining` — all of which only ever drain inside `loop()`) and opens `#ability-menu`, a dedicated overlay — not the shared `#overlay` that pause/game-over use, whose Reintentar/Menú buttons don't apply here. `choosingAbility` gates `loop()`, `togglePause()`, and the `keydown` handler (checked *before* the `KeyP` branch, so pause can't stack behind the chooser); inside it, `Escape` cancels for free, `Digit1`-`Digit5` pick directly, and `Space` is swallowed so it can't "click" a focused button. The list is rebuilt on *every* open (unlike the once-built `CHALLENGES` menu) because availability is dynamic — today only DESHACER (`abilityAvailable()`) can be disabled. Choosing one runs it through `runAbility()` (a `switch` on `id`, mirroring `applyPower()`'s shape); a `false` return means it couldn't apply (nothing fit) and the charge isn't spent — `chooseAbility()` only zeroes `energy`, shows the banner, and closes the menu on a truthy result.
  - **VIDENCIA** (`ver5`) sets `preview5Remaining` (in pieces, decremented in `spawn()`), which gates a second preview strip (`#queue-canvas`, `drawQueue()`) rendering `nextQueue[1..4]`. `drawPreview()` — centering a piece in a 4×4 tile, with an optional cell offset so several tiles pack into one canvas — is the shared helper `drawNext()`, `drawQueue()`, and `drawHold()` all call.
  - **INTERCAMBIO** (`cambiar`) replaces `current` with a fresh standard tetromino (never the same type, never a rare piece) at the spawn position — never at the piece's current `y`: a different shape partway down could overlap already-locked cells, and `merge()` writes unconditionally. Refused (no charge) if even the spawn position collides.
  - **LENTITUD** (`ralentizar`) sets `slowRemaining = SLOW_MS`, ticked down by `loop()`'s `dt` the same way `freezeRemaining` is. `dropInterval` itself is never touched — it stays the pure function of `level` that `clearLines()` recomputes and the undo snapshot stores verbatim; `effectiveDropInterval()` is a read-time multiplier instead.
  - **RESERVA** (`hold`) stores `current` in canonical form (`{type, power}`, rebuilt via `resetPiece()` at spawn position — never the live rotated shape), so recalling it never depends on how it was rotated when stored; the first use costs `nextQueue[0]` (refilled after), later uses swap with the held piece. Refused (no charge) if the incoming piece collides at spawn position. `resetPiece()` special-cases `type === POWER` (`makePiece(POWER)` would throw — `POWER` isn't in `PIECES`) so a banked power-up survives the round trip.
  - **DESHACER** (`deshacer`) restores from `undoSnapshot`, taken by `takeUndoSnapshot()` at the top of *every* `lockPiece()` (both branches) — so it always reverts the most recent lock, not whichever one happened to fill the bar. It restores `current` at its exact locked `x`/`y`/shape (a deep `clonePiece()`, not the spawn position — that exact position was already proven legal against the just-restored board, whereas the spawn slot might not be with a tall stack), the board, score/lines/level/`dropInterval`/`combo`/`btbTetris`/`linesSincePower`, and `nextQueue` (deep-cloned, since `queueRewards()` mutates it in place with `splice`). `linesSincePower` is deliberately included — without it, undo-then-reclear would cross the `POWER_LINES` threshold twice, a repeatable free power-up. `energy` is deliberately excluded — `chooseAbility()` already zeroed it when the charge was spent, so restoring it would refund the very charge that paid for the undo. `freezeRemaining`/`slowRemaining` restore via `Math.min(snapshot, current)`, never a plain overwrite: that one rule blocks both exploit directions at once — undoing a just-applied Congelar can only cancel it, never grant free time back, while undoing something else mid-freeze can't extend it either. BASURA rows pushed *after* the reverted lock (`garbageSinceLock`, incremented alongside `pushGarbageRow()` in `loop()`) are replayed post-restore — otherwise a restored board would silently delete real garbage; a replay that itself overflows still resolves through `loseChallenge()`. Deliberately **not** restored: `challengeRemaining` (real elapsed time, not board state) and `espejoAvisado` (so ESPEJO doesn't re-announce itself on recrossing level 2). `undoSnapshot = null` afterward — no double-undo.
- **Challenge mode** (`CHALLENGES`, `activeChallenge`): each entry is pure data, not a code branch — a field the entry doesn't declare simply doesn't activate that mechanic, and `CHALLENGES[0]` (`clasico`) has none, making free play a challenge like any other rather than a separate path. `activeChallenge` is never `null` (defaults to classic), so `updateHUD()` — called on every `keydown` — never needs a null check. `{icono, nombre, desc}` on each entry match `showBanner()`'s shape, so `startChallenge(id)` gets the mode-announcement banner for free.
  - `showMenu()`/`startChallenge(id)` gate everything before a run starts; `inMenu` blocks input and `togglePause()` so `P` can't "resume" a nonexistent game. `restartBtn` still calls `init()` directly, so `init()` deliberately never resets `activeChallenge` — only `startChallenge()` does — or "Reintentar" would silently drop the player back into Clásico.
  - **Objective / timer**: `checkObjective()` (`metaLineas`) runs inside `lockPiece()`, *before* `spawn()` — win must be decided first because `spawn()` can itself call `endGame()` on topout, and without that ordering a winning placement's overlay would get overwritten by a topout on the same frame (and `endGame()`'s `current = null` would immediately be undone by `spawn()`). `limiteMs` counts down in `loop()` using the same per-frame `dt` as `freezeRemaining` (see below), gated behind `activeChallenge.limiteMs` so classic mode does nothing extra; hitting 0 resolves to `winChallenge()` or `loseChallenge()` per `alAgotarse`.
  - **`DT_CAP`**: `loop()` clamps `dt = Math.min(ts - lastTime, DT_CAP)`. Previously an unclamped `dt` was nearly harmless (it just drained `freezeRemaining` and caused one drop); with a challenge clock, a backgrounded tab would otherwise zero it in one frame.
  - **GARBAGE / Basura**: `makeGarbageRow()` fills a row with `GARBAGE` (15) with one hole, reusing the same `garbageHoleCol` for a few rows (a fresh random hole every row would make garbage unclearable — only the bottom-most hole would ever be reachable). `prefillBoard(n)` uses the same helper for TABLERO SUCIO's starting rows. `pushGarbageRow()` (`basuraMs`, gated on `freezeRemaining === 0` so Congelar doesn't turn into a punishment) first checks `board[0]` for any block — a non-empty top row means the stack overflowed upward before the shift, which is BASURA's actual lose condition (without this check, `board.shift()` would silently delete overflow and the mode would be unlosable). It then shifts the board up one row and appends a new garbage row; since that moves every locked cell up exactly one row while `current` doesn't move, the falling piece can now overlap what's below it — resolved by moving `current.y` up by exactly one (mathematically exact for a single-row shift, not a heuristic), or losing if it still collides.
  - **FANTASMA**: `draw()` gates the entire locked-board render loop behind `showBoard = !activeChallenge.invisible || revealRemaining > 0 || gameOver`, so `drawNutHole`'s `destination-out` compositing and `WILD` rendering are simply skipped rather than special-cased. `lockPiece()` sets `revealRemaining = REVEAL_MS` after a normal or power-up lock. The ghost piece is deliberately *not* hidden — it leaks the stack height in the current column, but that's the intended concession that keeps the mode playable instead of purely memorization.
  - **ESPEJO**: `mirrorActive()` (`level >= espejoDesdeNivel`) switches `tryRotate()` to `rotateCCW` (three `rotateCW` calls — reuses the existing transpose logic, keeps the wall-kick loop untouched). The trigger is level 2, not 3, on purpose: `level = floor(lines/10)+1` means level 3 is exactly the 20-line win condition, so a level-3 trigger would never actually play. `announceMirrorIfNeeded()` (called from `clearLines()` after `level` updates) shows a one-time banner via `showBanner()` so the flipped rotation doesn't read as a bug.
  - **`powerTinte()` excludes `GARBAGE`** from its most-frequent-color count — otherwise, on any board with garbage, garbage is always the most frequent value, and Tinte would convert the entire garbage stack into walk-through `WILD` cells (`collide()` passes through `WILD`), trivializing BASURA/TABLERO SUCIO.
  - **`endRun(titulo, detalle, ganada)`** is the single end-of-run point (win or lose), replacing the old fixed-title `endGame()` (now a thin wrapper). It's idempotent (`if (gameOver) return`) because a win and a topout can both be reached in the same frame — e.g. `checkObjective()` winning right when `spawn()` would have topped out.
- **Wall kicks** (`tryRotate`): after rotating, tries offsets `[0, -1, 1, -2, 2]` until one doesn't collide.
- **Game loop** (`loop`): driven by `requestAnimationFrame`, accumulates elapsed time in `dropAccum` and advances the piece one row once `dropInterval` is exceeded; otherwise calls `lockPiece()`.
- **Line clearing** (`clearLines`): scans bottom-up, splices full rows out and unshifts empty rows at the top.
- **Scoring**: `LINE_SCORES = [0, 100, 300, 500, 800]` multiplied by `level`; hard drop adds 2 points/row dropped, soft drop adds 1 point/row.
- **Leveling/speed**: level = `floor(lines / 10) + 1`; `dropInterval = max(100, 1000 - (level - 1) * 90)` ms.
- **Ghost piece** (`ghostY`): projects the current piece straight down to its landing row, drawn at `globalAlpha = 0.2`.
- **Game over**: triggered in `spawn()` when a freshly spawned piece already collides.

Flow: `showMenu()` runs at load instead of `init()`. Picking a mode calls `startChallenge(id)`, which sets `activeChallenge` and only then calls `init()` — which builds the board (applying `prefill` if the challenge has one), seeds `nextQueue`, calls `spawn()`, and starts the `loop`. Keyboard input (`keydown`) handles move/rotate/soft-drop/hard-drop/pause/abilities; `P` toggles pause independent of `gameOver` state, but does nothing while `inMenu` or `choosingAbility`; `E` opens the ability chooser once `energy` is full, which does nothing while `inMenu`, `paused`, or `gameOver`.

### Tunable constants (top of `game.js`)

`COLS`, `ROWS`, `BLOCK`, `COLORS`, `LINE_SCORES`, `dropInterval`, `RARE_CHANCE` (odds of a rare piece — tuerca/pentominoes), `POWER_LINES` (lines between power-ups), `FREEZE_MS` (Congelar duration), `BANNER_MS` (banner visibility), `COMBO_CAP`, `TSPIN_SCORES`, `BTB_BONUS_RATIO`, `PERFECT_CLEAR_BONUS`, `CHALLENGES` (challenge catalog — objective/timer/garbage/mirror fields per entry), `REVEAL_MS` (FANTASMA reveal flash), `DT_CAP` (per-frame dt clamp), `PREVIEW_MAX` (minimum `nextQueue` depth / preview length), `ENERGY_MAX`/`ENERGY_PER_LINE` (ability-bar cap and per-line gain), `SLOW_MS`/`SLOW_FACTOR` (Lentitud duration/multiplier), `PREVIEW5_PIECES` (Videncia duration in placements), `ABILITIES` (ability catalog). If `COLS`/`ROWS`/`BLOCK` change, update the `#board` canvas `width`/`height` in `index.html` to match (`COLS × BLOCK`, `ROWS × BLOCK`).

## Automatización de issues

Al abrir un issue, o al editar su cuerpo, `.github/workflows/issue-triage.yml` corre a Claude automáticamente para clasificarlo y publicar un diagnóstico técnico como comentario (causa raíz con referencias `archivo:línea`, constantes afectadas, enfoque propuesto, criterios de aceptación). Si el issue menciona `@claude`, lo atiende en su lugar `.github/workflows/claude.yml`.

- **Etiquetas**: `.github/labels.yml` es la fuente de verdad de la taxonomía (`type/*`, `area/*`, `priority/*`, más `needs-info`, `duplicate`, `triaged`, `no-triage`). Se sincronizan a GitHub vía `.github/workflows/labels-sync.yml`; no edites las etiquetas manualmente en GitHub, edita ese archivo.
- **Escotilla manual**: aplicar la etiqueta `no-triage` a un issue impide que el triaje automático se ejecute sobre él.
